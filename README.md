# Попутчики — совместные путешествия

Приложение для публикации идей поездок, поиска попутчиков и совместного ведения плана, бюджета и чата.

**Стек:** React + TypeScript + Ant Design + Vite; FastAPI + Pydantic + SQLAlchemy; PostgreSQL; Docker Compose.

## Экраны и сценарии

| Адрес | Экран | Возможности |
|---|---|---|
| `/` | Поездки | Поиск по названию и направлению, фильтр «Все / Мои» |
| `/trips/:id` | Поездка | Просмотр, присоединение, пункты плана, расходы, чат |
| `/trips/new` | Новая поездка | Создание поездки с проверкой полей |
| `/profile` | Личный кабинет | Изменение имени и email |
| `/login`, `/register` | Вход и регистрация | Демо-формы с клиентской проверкой |

## Структура

### Frontend (`frontend/src`)

- `app/` — запуск и конфигурация приложения, маршруты и общий контекст данных.
- `pages/` — страницы поездок, формы, авторизации и профиля.
- `features/` — пользовательские действия и фильтры.
- `entities/` — типы предметной области и демонстрационные данные.
- `shared/` — общие элементы и утилиты (добавляются по мере необходимости).

Для внутренних импортов используется абсолютный алиас `@/`, настроенный в `frontend/tsconfig.json` и `frontend/vite.config.ts`.

### Backend (`backend/app`)

- `main.py` — приложение FastAPI, CORS и подключение маршрутов.
- `config.py`, `database.py`, `deps.py` — конфигурация, сессии БД и общие зависимости.
- `models/` — отдельные SQLAlchemy-модели пользователя, поездки, участника и содержимого поездки.
- `schemas/` — отдельные Pydantic-схемы пользователя, поездки и содержимого.
- `routers/` — HTTP-маршруты пользователей, поездок, плана, расходов и чата.

Python-модули импортируются от пакета `app`, например `from app.models import Trip`.

## Настройка и запуск

В корне проекта находится один локальный файл `.env`. Создайте его из шаблона один раз:

```powershell
Copy-Item .env.example .env
```

В `.env` находятся параметры PostgreSQL, URL базы и разрешённый адрес frontend. Файл `.env` игнорируется Git; секретные значения нельзя коммитить.

### Запуск PostgreSQL и backend через Docker

В первом окне PowerShell, из корня проекта:

```powershell
docker compose up --build
```

API: <http://localhost:8000>. Документация Swagger: <http://localhost:8000/docs>. Остановить сервисы: `Ctrl+C`.

### Запуск frontend

Во втором окне PowerShell:

```powershell
cd frontend
npm install
npm run dev
```

Откройте адрес Vite, <http://localhost:5173>.

### Сборка frontend

```powershell
cd frontend
npm run build
```

## Демонстрационные данные и состояние

Начальные поездки находятся в `frontend/src/entities/trip/demoData.ts`. Контекст `app/TripsContext.tsx` хранит изменения списка и профиля в `localStorage`. Создание поездки, изменение профиля, добавление пункта плана, расхода и сообщения работают локально в браузере. Очистить демо-состояние можно в инструментах разработчика браузера: **Application → Local Storage → localhost → удалить `travel-trips` и `travel-profile`**, затем обновить страницу.

Поля форм показывают ошибки валидации. Список поездок показывает пустое состояние, если фильтр ничего не нашёл; неверный id поездки отображает ошибку. CSS-анимация `fade-in` применяется при открытии форм и страницы поездки.

## Модель данных backend

- `users`: id, email, name.
- `trips`: название, направление, описание, даты, максимальное число участников, организатор.
- `members`: связь пользователя и поездки; пара поездка-пользователь уникальна.
- `plan_items`: пункты плана поездки.
- `expenses`: расходы и пользователь, который их оплатил.
- `messages`: сообщения и их авторы.

Backend использует `X-User-Id` как временный способ определить пользователя. Это не полноценная аутентификация и не должно использоваться в production. Для локальной разработки модели создают таблицы при запуске приложения.
