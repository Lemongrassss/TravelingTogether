# Попутчики — совместные путешествия

Приложение для публикации идей поездок, поиска попутчиков и совместного ведения плана, бюджета и чата.

**Стек:** React + TypeScript + Ant Design + Vite; FastAPI + Pydantic + SQLAlchemy; PostgreSQL; Docker Compose.

## Экраны и сценарии

| Адрес | Экран | Возможности |
|---|---|---|
| `/` | Поездки | Поиск по названию и направлению, фильтр «Все / Мои» |
| `/trips/:id` | Поездка | Просмотр, присоединение, пункты плана, расходы, чат |
| `/trips/new` | Новая поездка | Создание поездки с проверкой полей |
| `/profile` | Личный кабинет | Данные аккаунта, статистика и выход |
| `/login`, `/register` | Вход и регистрация | Создание учётной записи и вход через API |

## Структура

### Frontend (`frontend/src`)

- `app/` — запуск и конфигурация приложения, маршруты и общий контекст данных.
- `pages/` — страницы поездок, формы, авторизации и профиля.
- `features/` — пользовательские действия и фильтры.
- `entities/` — типы предметной области и демонстрационные данные.
- `shared/` — общие элементы и утилиты (добавляются по мере необходимости).

Для внутренних импортов используется абсолютный алиас `@/`, настроенный в `frontend/tsconfig.json` и `frontend/vite.config.ts`.

### Backend (`backend/app`)

- `main.py` — приложение FastAPI, CORS, маршруты и добавление колонки пароля для существующей базы.
- `config.py`, `database.py`, `deps.py` — конфигурация, сессии БД и общие зависимости.
- `models/` — отдельные SQLAlchemy-модели пользователя, поездки, участника и содержимого поездки.
- `schemas/` — отдельные Pydantic-схемы пользователя, поездки и содержимого.
- `routers/` — HTTP-маршруты пользователей, поездок, плана, расходов и чата.
- `routers/auth.py` — регистрация, вход, обновление токенов, текущий пользователь и выход.

Python-модули импортируются от пакета `app`, например `from app.models import Trip`.

## Настройка и запуск

В корне проекта находится один локальный файл `.env`. Создайте его из шаблона один раз:

```powershell
Copy-Item .env.example .env
```

В `.env` находятся параметры PostgreSQL, URL базы, адрес frontend и `AUTH_SECRET_KEY`. Если `.env` создан раньше, добавьте туда `AUTH_SECRET_KEY` из `.env.example`. Файл `.env` игнорируется Git; секретные значения нельзя коммитить.

### Запуск всего проекта через Docker

В первом окне PowerShell, из корня проекта:

```powershell
docker compose up --build
```

Compose запускает PostgreSQL, backend и frontend. После готовности откройте:

- Интерфейс: <http://localhost:5173>
- API: <http://localhost:8000>
- Swagger: <http://localhost:8000/docs>

Остановить все контейнеры можно сочетанием `Ctrl+C`. Для запуска в фоне используйте `docker compose up --build -d`, для остановки — `docker compose down`.

Для frontend отдельно Dockerfile запускает Vite на `0.0.0.0`, а Compose ждёт готовности backend перед запуском frontend.

### Локальный запуск frontend без Docker 

Если нужно отдельно разрабатывать интерфейс, откройте второе окно PowerShell:

```powershell
cd frontend
npm install
npm run dev
```

Vite будет доступен по адресу <http://localhost:5173>.

### Сборка frontend

```powershell
cd frontend
npm run build
```

## Аутентификация

Пароли новых пользователей хранятся в виде Argon2-хешей. При входе backend выдаёт access JWT на 15 минут и refresh token на 7 дней. Refresh token хранится в БД только в виде SHA-256-хеша; при обновлении он заменяется новым, при выходе отзывается.

- `POST /auth/register` — регистрация и выдача токенов.
- `POST /auth/login` — вход и выдача токенов.
- `POST /auth/refresh` — обновление пары токенов по refresh token.
- `GET /auth/me` — текущий пользователь; нужен `Authorization: Bearer <access_token>`.
- `POST /auth/logout` — отзыв refresh token текущей сессии.

Защищённые маршруты принимают access token в заголовке `Authorization: Bearer ...`. Frontend хранит токены в `localStorage`, загружает текущего пользователя при открытии и пробует обновить access token через refresh token. Страницы профиля и создания поездки требуют входа. Старые пользователи, созданные до добавления пароля, не смогут войти без пароля — для демонстрации зарегистрируйте новый email.

## Демонстрационные данные и состояние

Начальные поездки находятся в `frontend/src/entities/trip/demoData.ts`. Контекст `app/TripsContext.tsx` хранит изменения списка и профиля в `localStorage`. Создание поездки, изменение профиля, добавление пункта плана, расхода и сообщения работают локально в браузере. Очистить демо-состояние можно в инструментах разработчика браузера: **Application → Local Storage → localhost → удалить `travel-trips` и `travel-profile`**, затем обновить страницу.

Поля форм показывают ошибки валидации. Список поездок показывает пустое состояние, если фильтр ничего не нашёл; неверный id поездки отображает ошибку. CSS-анимация `fade-in` применяется при открытии форм и страницы поездки.

## Модель данных backend

- `users`: id, email, name.
- `trips`: название, направление, описание, даты, максимальное число участников, организатор.
- `members`: связь пользователя и поездки; пара поездка-пользователь уникальна.
- `plan_items`: пункты плана поездки.
- `expenses`: расходы и пользователь, который их оплатил.
- `messages`: сообщения и их авторы.

При старте backend создаёт недостающие таблицы; для существующей базы добавляется колонка `hashed_password`. Обновление токенов хранится в отдельной таблице `refresh_tokens`.
